# OffTheBall · 오프더볼 0.3

축구 영상에서 선수를 탐지·추적하고 팀 배치, 간격, 포메이션 변화를 전술 보드로 확인하는 분석 프로그램입니다. Windows 데스크톱 UI와 Google Colab GPU 전체 영상 분석을 지원합니다.

## 실행
1. 이 폴더의 **실행.cmd**를 엽니다.
2. 영상 파일을 선택해 **영상 분석 시작**, 또는 **태블릿 카메라 연결**을 누릅니다.
3. 태블릿 주소는 기본값 http://10.50.75.89:8080 입니다. IP Webcam 서버를 켜고 PC와 같은 네트워크에 연결하세요.
4. 중지하려면 **분석 중지**를 누릅니다.

현재 PC에는 필요한 모델과 의존성이 설치되어 있습니다. 업데이트 전에 열어둔 프로그램은 닫고 다시 열어야 새 코드가 적용됩니다.

## 이번 버전
- YOLO11n과 ByteTrack으로 같은 장면의 사람을 탐지·추적합니다.
- 상의 색상으로 팀 A/B를 추정합니다. A는 파란 박스, B는 빨간 박스, ?는 미확인입니다.
- 표시 색은 팀 이름이나 실제 유니폼 색을 뜻하지 않습니다. 새 입력에서는 A/B 대응이 달라질 수 있습니다.
- 관측된 각 사람의 최근 15개 위치를 화면상 궤적으로 표시합니다.
- 사용자가 지정한 그라운드 경계 안에 발 위치가 있는 사람만 전술 분석에 포함합니다.
- 수동 또는 자동 경기장 보정을 적용하면 전술 보드, 팀 폭, 평균 편차, 최근접 간격을 미터 좌표로 계산합니다.
- 기준 포메이션을 드래그해 저장하고 현재 선수 배치와 비교할 수 있습니다.
- 영상 시간바 탐색·일시정지와 전술 이벤트 기록을 지원합니다.
- 장면 전환·입력 크기 변경·시각 역전·긴 입력 공백·검은 화면 뒤에는 번호와 궤적을 초기화합니다.
- 장면 전환 때 기존 유니폼 색상 기준은 유지하고, 번호에 연결된 분류 기록은 비웁니다.
- 파일 분석 결과에는 scene_id와 track_id를 함께 저장합니다.

## 해석할 때 알아둘 점
- 임시 번호는 실제 등번호나 선수 이름이 아닙니다. 가림, 탐지 누락, 빠른 카메라 이동 때문에 번호가 바뀔 수 있습니다.
- 팀 색상 분류는 추정입니다. 두 유니폼의 색이 비슷하거나 조명이 달라지면 오분류/미분류가 생길 수 있습니다.
- 심판과 골키퍼를 전문적으로 식별하는 모델은 없습니다. 다른 색은 보통 미확인으로 남지만 이를 보장하지 않습니다.
- 장면 전환 감지는 보조 규칙이며 모든 전환을 완벽하게 찾는 기능은 아닙니다.
- 화면상 궤적에는 카메라 이동이 섞입니다. 실제 거리, 속도, 전술 움직임으로 해석하면 안 됩니다.
- 실시간 입력은 오래된 프레임을 버려 지연 누적을 줄입니다. 파일 분석은 모든 프레임을 처리합니다.

## 입력 방식
### 영상 파일
MP4/AVI 등 로컬 파일을 읽습니다. 분석 중지·실패 시 이미 처리한 부분과 상태를 저장합니다.

### 태블릿 카메라
IP Webcam의 기본 페이지 주소 또는 HTTP MJPEG 영상 주소를 입력합니다.
기본 주소는 /video로 연결합니다. 영상이 끊기거나 유효 프레임이 오지 않으면 이전 화면을 지우고 오류를 알립니다.
다시 연결하려면 서버 상태를 확인하고 **태블릿 카메라 연결**을 다시 누릅니다. 자동 재접속은 하지 않습니다.
영상 수신 시각은 PC 기준이며 카메라 촬영 시각이나 전체 지연 측정값이 아닙니다.

### 화면 영역
화면 캡처도 남겨두었습니다. 영역은 왼쪽, 위쪽, 너비, 높이를 입력합니다.
쿠팡플레이 직접 캡처는 사용자 테스트에서 검게 나타났으므로 현재는 태블릿 카메라 입력을 사용합니다.

## 정지 장면 거리 실험
1. 영상을 열거나 분석을 중지한 뒤 **현재 장면 거리 보정**을 누릅니다.
2. 실제 위치를 알고 있는 경기장 지점 4개 이상을 클릭하고 같은 좌표계의 X,Y(미터)를 입력합니다.
3. **보정 계산** 후 기준점 영역 안 두 지점을 클릭합니다.
4. **보정·장면 저장**으로 해당 정지 이미지와 보정을 남깁니다.

보정된 경기장 좌표가 있는 선수는 전술 보드와 간격 지표에 반영합니다. 미터 단위 계산은 보정 정확도에 영향을 받습니다.

## 결과 파일
파일 분석마다 outputs 안에 새 폴더를 만듭니다. 아래 MP4와 요약 파일은 전체 영상 내보내기에서 생성하며, 시간바를 사용하는 대화형 분석은 frames.jsonl을 저장합니다.
- analysis.mp4: 팀 색·번호·이동선 표시 영상, 오디오 없음
- frames.jsonl: 프레임 시각, 박스, 팀, 장면 번호, 추적 번호, 화면상 궤적
- summary.json: 상태와 처리 성능
- calibration.json / frame.png: 수동 보정을 저장할 때 생성

태블릿·화면 입력은 현재 미리보기만 제공하며 영상과 좌표 로그를 자동 저장하지 않습니다.
결과 영상은 원본 명목 FPS를 사용하므로 가변 프레임률 입력의 원본 재생 시간 보존은 미지원입니다.

## 설치와 개발
Python 3.13과 uv가 준비된 환경에서 **설치.cmd**를 실행합니다.
requirements.lock.txt에 검증 환경의 의존성을 고정했습니다.
최초 설치·모델 다운로드 이후 기본 분석에는 외부 AI API가 필요하지 않습니다.

~~~powershell
$env:PYTHONPATH = "$PWD\src"
.\.venv\Scripts\python.exe -m offtheball gui
.\.venv\Scripts\python.exe -m offtheball analyze "영상의 절대 경로.mp4"
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider --basetemp=work\test-new-run
~~~

임시 테스트 폴더는 매 실행마다 새 이름을 사용하세요.

## Google Colab GPU 분석
1. [OffTheBall_Colab.ipynb](OffTheBall_Colab.ipynb)을 Google Colab에서 엽니다.
2. 런타임 유형을 T4 GPU로 변경합니다.
3. 첫 셀을 실행해 공개 GitHub 저장소의 `main` 브랜치를 `/content/OffTheBall`에 얕게 복제하고 필요한 패키지를 설치합니다.
4. 나머지 셀을 위에서부터 실행하고 경기 영상 한 개를 업로드합니다.
5. 마지막 셀에서 분석 영상과 JSON 기록이 담긴 ZIP을 받습니다.

코랩에서는 데스크톱 UI, 화면 캡처, 태블릿 실시간 연결을 사용하지 않습니다. 녹화된 영상의 전체 분석에 사용합니다. `PersonDetector`의 기본 장치는 `auto`이므로 CUDA가 있으면 GPU를, 없으면 CPU를 선택합니다.
용량이 큰 전체 경기 영상은 업로드 셀의 `USE_GOOGLE_DRIVE`를 `True`로 바꾸고 `DRIVE_VIDEO`에 Drive 경로를 입력할 수 있습니다.

저장소 복제는 한 번에 45초, 최대 두 번 시도합니다. 저장소가 공개되어 있으므로 GitHub 토큰은 필요하지 않습니다. 복제가 실패하면 출력된 Git 오류와 Colab의 인터넷 연결을 확인한 뒤 런타임을 재시작하고 첫 셀부터 다시 실행하세요. 첫 셀은 기존 `/content/OffTheBall` 폴더를 지우고 새로 복제합니다.

## 새 분석 화면
- 상단에 주요 메뉴, 왼쪽에 영상과 시간바, 오른쪽에 전술 보드·간격 지표·이벤트 목록을 배치했습니다.
- 영상 파일을 연 뒤 시간바를 클릭하거나 드래그하면 원하는 장면으로 이동합니다. 분석 중에도 이동·일시정지가 가능합니다.
- 첫 분석 시 화면에 보이는 그라운드 경계를 선택합니다. 발 위치가 경계 안인 사람만 추적하며, 미터 좌표 입력과는 별개입니다. 입력을 바꾸면 경계를 다시 선택해야 합니다.
- 태블릿·화면 입력은 처음에는 미리보기입니다. 중지 후 **더보기 → 그라운드 영역 선택**을 하고 같은 입력에 다시 연결하면 추적합니다.
- 경기장 좌표 보정을 적용해야 전술 보드에 선수 위치와 미터 단위 간격이 표시됩니다.
- 대화형 파일 분석은 처리한 프레임을 `frames.jsonl`로 저장합니다. 전체 영상 파일이 필요하면 더보기의 전체 영상 내보내기를 사용합니다.
- 현재 지표와 포메이션 비교는 관측된 선수와 보정 품질에 영향을 받으며, 공 소유권이나 공격·수비 상황을 자동 확정하지 않습니다.

## 브랜치 규칙
- `main`: 안정 기준. 직접 커밋하지 않고 PR로만 갱신합니다.
- `develop`: 업데이트용 기본 브랜치. 기능 브랜치(`codex/<이름>`)를 여기서 따서 PR로 병합하고 병합 후 삭제합니다.
- `hotfix`: 급한 수정용. `main`에서 따서 `main`으로 PR을 올리고, 병합 후 `develop`에도 반영합니다.
- PR은 squash로 병합합니다.
