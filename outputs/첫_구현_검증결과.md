# 첫 구현 검증 결과

검증일: 2026-09-15

## 구현 결과

실행.cmd로 한국어 프로그램을 열 수 있도록 구성했습니다.

- 영상 선택, 사람 탐지, 박스 표시
- 처리 결과 MP4와 프레임별 데이터 저장
- 중지 및 오류 발생 시 부분 결과 정리
- 화면 영역 지정과 탐지 미리보기
- 정지 장면의 경기장 기준점 수동 보정 및 두 지점 거리 측정
- 검은 화면 감지, 탐지 생략, 입력 확인 안내

팀 분류·선수 ID 추적·움직이는 영상의 자동 거리 표시는 아직 구현하지 않았습니다.

## 자동 검증

38개 통과. 입력, 좌표 변환, 파일 저장, 중지, 실패 복구, 해상도 변경, 홀수 크기, 한글 경로, 이전 미리보기 제거, 검은 영상 처리, 숨겨진 GUI 조작을 확인했습니다.

GUI 테스트가 여러 Tk 인터프리터를 연속 생성할 때 기존 Python 설치의 Tcl 파일을 간헐적으로 읽지 못했습니다. 테스트를 실제 앱처럼 단일 Tk 인터프리터를 사용하는 구조로 수정한 뒤 전체 검증을 통과했습니다. 실제 사용자 화면에 대한 시각 검수는 남아 있습니다.

## 실제 모델 실행

공식 YOLO11n 모델의 일반 인물 예제로 4명을 탐지했고, 12프레임 결과 MP4 저장에 성공했습니다.

- CPU, 모델 입력 크기 960
- 예제의 후속 12프레임 처리 약 6.63fps
- 해당 실행의 첫 추론 약 3.59초
- 작은 예제 영상 반복 시험이므로 실제 경기의 정확도·속도나 장시간 실시간 성능을 뜻하지 않습니다.

## 사용자 녹화본 확인

파일: manvsmci.mp4

- 메타데이터: 1920×1080, 30fps, 약 51.07초, 1532프레임
- 실제 순차 디코딩: 1531프레임
- 중앙 영상 영역의 검은 화면 판정: 1272프레임, 약 83.1%
- 긴 검은 구간: 약 6.47~48.80초
- 앞부분에도 재생기 메뉴만 보이며 주 경기 화면은 검게 저장되어 있습니다.
- 시작과 끝에는 녹화 프로그램 화면이 보입니다.
- 원인 자체는 조사하지 않았습니다. 녹화본만으로 캡처 제한인지 다른 설정 문제인지 확정할 수 없습니다.

픽셀 검사는 프레임 중앙 80% 영역 중 98% 이상이 거의 검고 평균 밝기도 낮은지 확인합니다. 이 판정 비율은 경기 영상이 정상인 비율의 반대값을 뜻하지 않습니다. 나머지 구간에도 메뉴·녹화 화면이 포함됩니다.

이 입력으로 선수 탐지 정확도나 경기장 거리 오차를 검증할 수 없습니다. 전체 모델 분석은 불필요해 중단했고, 해당 실행 폴더의 summary.json에 중단 사유를 남겼습니다. 그 폴더의 미완성 MP4는 사용 가능한 결과 영상이 아닙니다.

## 다음 단계

현재 필요한 입력은 재생했을 때 경기장이 실제로 보이는 30~60초 영상입니다. 준비되면 넓은 장면의 탐지 정확도와 경기장 거리 보정을 먼저 평가하고, 그 결과를 기준으로 팀 분류·추적을 구현합니다.
