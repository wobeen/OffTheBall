### 구현 단위 1 — 분석 모듈 경계와 보정 진단

상태: 구현 및 자동 테스트 완료, 사용자 커밋 대기

#### 수정한 코드와 이유

- `src/offtheball/contracts.py` 신규 추가
  - 탐지기, 추적기, 팀 분류기, 경기장 보정기가 따라야 할 구조적 인터페이스를 정의했다.
  - 이후 ByteTrack과 BoT-SORT, 수동 보정과 키포인트 자동 보정을 교체 실험할 때 핵심 분석 세션이 특정 라이브러리에 종속되지 않게 하기 위한 변경이다.
  - 기존 클래스가 새 부모 클래스를 상속하도록 강제하지 않으므로 현재 런타임 동작에는 영향이 없다.

- `src/offtheball/calibration.py`
  - `ManualCalibration`에 보정 출처, 상태, 기준점 개수 등을 반환하는 `diagnostics()`를 추가했다.
  - `AutoPitchCalibration`에 마지막으로 경기장 영역을 확인한 뒤 지난 프레임 수와 stale 기준을 추가했다.
  - 자동 보정 근거가 오랫동안 관측되지 않았다는 사실을 기록할 수 있게 하기 위한 변경이다.
  - 이번 단위에서는 stale 상태여도 기존 투영 결과를 숨기지 않는다. 좌표 차단은 키포인트 기반 자동 보정과 품질 검증을 구현한 뒤 적용한다. 따라서 기존 GUI 동작은 유지된다.

- `src/offtheball/analysis.py`
  - 보정이 없음, 기존 방식 보정, 새 진단 지원 보정을 동일한 JSON 구조로 정규화하는 `calibration_diagnostics()`를 추가했다.
  - 잘못된 상태 문자열이나 `NaN` 진단값이 결과 JSON을 손상하지 않도록 방어 처리를 넣었다.
  - 과거 방식의 보정 객체도 계속 사용할 수 있어 하위 호환성이 유지된다.

- `src/offtheball/pipeline.py`
  - 전체 영상 분석의 `frames.jsonl` 각 행에 `schema_version: 2`, `calibration_status`, `calibration`을 기록한다.
  - `summary.json`에도 `schema_version: 2`를 기록한다.
  - 향후 보정 방식과 신뢰도를 결과만 보고도 판별하고, 출력 형식 변경을 명시적으로 관리하기 위한 변경이다.
  - 기존 필드는 삭제하거나 이름을 바꾸지 않았으므로 기존 소비자는 추가 필드를 무시하고 계속 읽을 수 있다.

- `src/offtheball/playback.py`
  - 시간바 기반 대화형 분석 결과에도 전체 영상 분석과 같은 스키마 및 보정 진단 필드를 기록한다.
  - 두 분석 경로에서 서로 다른 형식의 `frames.jsonl`이 만들어지는 문제를 막기 위한 변경이다.

- `tests/test_calibration.py`, `tests/test_analysis.py`, `tests/test_pipeline.py`
  - 수동 보정 진단, 자동 보정 stale 상태, 보정이 없는 경우, 과거 방식 보정 객체 호환, 스키마 버전과 저장 필드를 검증하는 테스트를 추가했다.
  - 진단 기능이 기존 좌표 투영과 영상 분석을 바꾸지 않는지도 함께 확인한다.

- 영상 분석 화면, 탐지, 추적, 팀 분류, 좌표 투영 방식은 바뀌지 않는다.
- 새 결과 파일에는 보정의 유무와 출처를 설명하는 정보가 추가된다.

- 출력 스키마가 버전 2로 표시되지만 기존 필드는 유지된다.
- 앞으로 키포인트 보정이나 다른 추적기를 추가할 때 핵심 세션을 크게 고치지 않고 어댑터 형태로 연결할 기반이 생겼다.

#### 사용자가 직접 확인할 항목

1. 보정 없이 짧은 영상을 분석한다.
2. 새 `outputs/<분석 폴더>/frames.jsonl` 첫 행에 `schema_version`이 `2`인지 확인한다.
3. 같은 행의 `calibration_status`가 `not_calibrated`이고 `calibration.source`가 `null`인지 확인한다.
4. 경기장 보정을 저장하고 같은 방식으로 분석한다.
5. 새 결과의 `calibration_status`가 `active`이고 수동 보정이라면 `calibration.source`가 `manual_fixed_frame`인지 확인한다.
6. 선수 박스, 팀 A/B, 임시 번호, 궤적, 시간바, 전술 보드가 이전과 동일하게 작동하는지 확인한다.
7. 기존에 생성한 결과 파일을 다시 열 수 있는지 확인한다.

정상 결과는 분석과 UI 동작이 이전과 같고 결과 JSON에 진단 필드만 추가되는 것이다. 분석 중단, 빈 결과 파일, 보정하지 않았는데 미터 좌표가 표시되는 현상, 시간바와 전술 보드의 프레임 불일치는 실패로 본다.

## 쿠팡플레이 녹화 검은 화면 원인 (2026-09-15)

- 증상: 쿠팡플레이 재생 화면을 녹화하면 결과 파일이 검게 나옴.
- 원인: 녹화(파일 저장)든 실시간 분석이든 두 방식 모두 화면 캡처 단계를 먼저 거친다. 차단이 캡처 단계에서 발생하면 저장 여부와 무관하게 동일하게 검게 나온다.
- 근거: Windows는 Desktop Duplication API 등에서 보호된(DRM) 영상 콘텐츠에 대한 캡처를 제한한다. 참고: https://learn.microsoft.com/en-us/windows-hardware/drivers/display/desktop-duplication-api
- 확인 방법: 프로그램의 '화면 영역 분석' 기능으로 쿠팡플레이 재생 화면을 실시간 캡처해본다.
  - 정상적으로 잡히면: 캡처 자체는 문제 없음 → 이전 녹화본이 검게 나온 원인은 녹화/저장 과정 쪽일 가능성이 큼 → 실시간 분석 진행.
  - 검게 나오면: 캡처 단계 자체가 차단된 것 → 현재 방식으로는 쿠팡플레이 재생 화면 분석이 어려움.
- 결론: 사용자 확인 결과 실시간 분석에서도 검게 나옴 → 캡처 문제로 확정. 쿠팡플레이의 보호 기능(DRM)에 의한 캡처 차단으로 판단됨.
- 후속 과제: 캡처 차단을 우회할 수 없다는 전제 하에, 대체 입력 경로(예: 비보호 소스, 별도 캡처 장치/HDMI 캡처보드 등)를 검토할 필요가 있음.

## 모델 역할 분담

중요한 기획·설계 판단과 최종 검토는 Astra가 총괄하고, 구현·반복 검증·자료 처리 등 토큰 소모가 큰 작업은 Luna 하위 에이전트를 기본으로 사용한다. 필요할 때만 상위 모델을 사용한다.
