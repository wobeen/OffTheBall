- 44개 자동 검증 통과
- 실제 모델의 일반 인물 예제 추론 및 12프레임 영상 저장 확인

## 검증의 한계

- 자동 검증은 합성 영상, 모의 화면 입력, 수학적 보정과 숨겨진 UI 동작 검사다.
- 실제 사람 탐지는 모델에 포함된 일반 인물 이미지로 확인했다.
- 교체된 manvsmci.mp4는 약 32.77초 경기 화면이다. 전체 980프레임 탐지 및 결과 재생 검증 완료, 검은 프레임 0개. 이전 검은 녹화본의 기록은 과거 결과로 보존한다.
- 축구 선수 탐지 정밀도/재현율, 실제 거리 오차, 팀 분류와 추적은 미검증/미구현이다.
- 화면 영역 캡처와 쿠팡플레이 중계 화면은 DRM 차단으로 검은 프레임이 될 수 있다. 태블릿 IP Webcam 입력은 아래 별도 실측을 완료했다.
- 수동 보정은 정지 장면 실험이다. 영상 위 자동 거리 표시는 구현하지 않았다.
- 화면 캡처는 최신 프레임을 순차 처리하고 UI 미리보기 대기열을 한 개로 제한했다. 캡처·추론 완전 분리, 입력 동결 감지, 장시간 안정성 검증은 후속 작업이다.
- 실제 화면의 시각적 UI 검수와 사용자 사용감 검수는 남아 있다.
- 기본 모델 입력 크기는 960, CPU 4스레드 추론이다. Intel GPU 가속은 적용하지 않았다.

## 태블릿 IP Webcam 실측 (2026-09-15)

- 사용자 제공 주소 `http://10.50.75.89:8080/`에 짧게 연결해 HTTP 200과 IP Webcam 페이지를 확인했다.
- 페이지가 확인한 표준 스트림 주소 `http://10.50.75.89:8080/video`는 `multipart/x-mixed-replace` JPEG 스트림으로 응답했다.
- 실제 스트림에서 1920×1080 JPEG 한 프레임을 디코드했다. 진단 이미지는 [work/tablet/diagnostic.jpg](../work/tablet/diagnostic.jpg)에 한 장만 저장했다.
- 네트워크 입력은 프레임 수신·디코드 시각을 로컬 경과 시간으로 기록한다. 이를 카메라 촬영 시각이나 종단 간 지연으로 해석하지 않는다.
- 직접 연결이 순간적으로 끊겨도 오류를 자격 증명 없이 표시하고, 이전 화면과 탐지 결과를 지운 뒤 종료한다. 자동 재연결은 구현하지 않았으며 사용자가 연결 버튼으로 다시 시작한다.

## 쿠팡플레이 녹화 검은 화면 원인 (2026-09-15)

- 증상: 쿠팡플레이 재생 화면을 녹화하면 결과 파일이 검게 나옴.
- 원인: 녹화(파일 저장)든 실시간 분석이든 두 방식 모두 화면 캡처 단계를 먼저 거친다. 차단이 캡처 단계에서 발생하면 저장 여부와 무관하게 동일하게 검게 나온다.
- 근거: Windows는 Desktop Duplication API 등에서 보호된(DRM) 영상 콘텐츠에 대한 캡처를 제한한다. 참고: https://learn.microsoft.com/en-us/windows-hardware/drivers/display/desktop-duplication-api
- 확인 방법: 프로그램의 '화면 영역 분석' 기능으로 쿠팡플레이 재생 화면을 실시간 캡처해본다.
  - 정상적으로 잡히면: 캡처 자체는 문제 없음 → 이전 녹화본이 검게 나온 원인은 녹화/저장 과정 쪽일 가능성이 큼 → 실시간 분석 진행.
  - 검게 나오면: 캡처 단계 자체가 차단된 것 → 현재 방식으로는 쿠팡플레이 재생 화면 분석이 어려움.
- 결론: 사용자 확인 결과 실시간 분석에서도 검게 나옴 → 캡처 문제로 확정. 쿠팡플레이의 보호 기능(DRM)에 의한 캡처 차단으로 판단됨.
- 후속 과제: 캡처 차단을 우회할 수 없다는 전제 하에, 대체 입력 경로(예: 비보호 소스, 별도 캡처 장치/HDMI 캡처보드 등)를 검토할 필요가 있음.

## 모델 역할 분담

중요한 기획·설계 판단과 최종 검토는 Astra가 총괄하고, 구현·반복 검증·자료 처리 등 토큰 소모가 큰 작업은 Luna 하위 에이전트를 기본으로 사용한다. 필요할 때만 상위 모델을 사용한다.

## 태블릿 입력 최종 보충 (2026-09-15)

- `http://10.50.75.89:8080/video`에서 1920×1080 JPEG 프레임을 실제로 디코드했다.
- 최신 프레임 한 개만 유지하며, 새 유효 프레임이 5초 이상 없으면 입력을 끊고 화면과 탐지 결과를 지운다.
- 연결 종료 뒤 자동 재연결은 하지 않는다. 사용자가 **태블릿 카메라 연결**을 다시 눌러 연결한다.
- 현재 자동 검증은 44개 통과했다. 표시 시간은 PC 수신·디코드 이후 경과 시간이며 카메라 촬영 시각이나 종단 간 지연이 아니다.
