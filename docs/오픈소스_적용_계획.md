# 오픈소스 참고 기능 적용 계획

- 작성일: 2026-09-22
- 작업 브랜치: `codex/oss-inspired-upgrades`
- 대상 버전: OffTheBall 0.2 이후
- 상태: 계획 수립 완료, 구현 미착수

## 1. 목표

현재의 사람 탐지, ByteTrack 임시 ID, 유니폼 색상 기반 팀 분류, 수동 경기장 보정, 전술 보드를 유지하면서 검증된 오픈소스의 설계와 알고리즘을 선별 적용한다.

우선순위는 다음과 같다.

1. 움직이는 카메라에서도 경기장 좌표가 갑자기 튀지 않는 자동 보정
2. 가림과 카메라 이동에서 추적 ID 전환 감소
3. 팀 분류의 시간적 안정성과 미확인 처리 개선
4. 선수·심판·골키퍼·공을 구분할 수 있는 축구 전용 탐지 경로
5. 공 위치를 근거로 한 점유율과 단순 패스 후보 표시
6. 결과의 정확도와 한계를 사용자가 확인할 수 있는 진단 정보

## 2. 적용 원칙

- 저장소 전체를 병합하지 않고 필요한 아이디어와 작은 모듈만 독립적으로 적용한다.
- 현재 수동 보정은 정확도 비교용 기준이자 자동 보정 실패 시 대체 경로로 유지한다.
- 자동 분석 결과에는 신뢰도, 보정 출처, 마지막 유효 보정 시각을 함께 저장한다.
- 실제 정답 데이터로 통과 기준을 확인하기 전에는 거리, 속도, 패스 등을 사실처럼 표현하지 않는다.
- 새 기능은 설정으로 끌 수 있어야 하며 기존 파일 분석 흐름을 깨뜨리지 않아야 한다.
- 외부 코드나 모델을 도입할 때 소스 URL, 기준 커밋, 라이선스, 수정 내용을 `THIRD_PARTY_NOTICES.md`에 기록한다.
- MIT라고 표시된 상위 저장소라도 모델 가중치, 데이터셋, Ultralytics, 하위 포함 코드의 라이선스는 별도로 확인한다.
- GPL-2.0인 PnLCalib는 먼저 별도 실험으로 성능만 비교한다. 배포 코드에 포함하는 결정은 라이선스 검토 후 별도로 한다.

## 3. 참고 대상과 사용 범위

### Simo-03/football-player-detection

- URL: <https://github.com/Simo-03/football-player-detection>
- 참고 범위: 32개 경기장 키포인트, RANSAC 보정 검증, 이전 보정 제한적 재사용, BoT-SORT 설정, 공 전용 검출, 점유율·패스·히트맵 구조
- 현재 프로젝트와 같이 Python 3.13 및 Ultralytics 계열을 사용하므로 첫 번째 비교 대상으로 삼는다.
- 코드를 가져올 경우 MIT 고지와 원본 경로를 남긴다.

### roboflow/sports

- URL: <https://github.com/roboflow/sports>
- 참고 범위: 표준 경기장 좌표 모델, 키포인트-경기장 대응, 전술 레이더 렌더링, 팀 분류 파이프라인
- 완성 앱으로 합치기보다 경기장 자료구조와 변환·시각화 설계의 기준으로 사용한다.

### SoccerNet/sn-gamestate

- URL: <https://github.com/SoccerNet/sn-gamestate>
- 참고 범위: 역할·팀·등번호가 포함된 경기 상태 표현, 추적 평가 방법, GS-HOTA/HOTA 계열 검증 절차
- 런타임 의존성이 무거우므로 제품 코드에 직접 결합하지 않고 평가 데이터와 지표 설계에 우선 사용한다.

### MatchVision AI

- URL: <https://github.com/BlazeWild/MatchVision-AI-Sports-Video-Analytics-Tracking-Pipeline>
- 참고 범위: 절대 보정 키프레임 사이의 광학 흐름, 물리적으로 불가능한 이동 제거, 보정 진단, 영상·전술 보드 동기 탐색
- 프로젝트 이력이 짧으므로 구현을 그대로 신뢰하지 않고 아이디어별로 재검증한다.

### PnLCalib

- URL: <https://github.com/mguti97/PnLCalib>
- 참고 범위: 경기장 점과 선을 함께 이용하는 자동 카메라 보정의 정확도 비교
- GPL-2.0, 별도 가중치, 높은 연산량 때문에 초기 제품 의존성에는 넣지 않는다.

## 4. 현재 기준선

현재 구현은 다음 기능을 이미 가진다.

- 일반 사람 YOLO 탐지와 Ultralytics ByteTrack
- 트래커 투입 전 경기장 다각형 외부 탐지 제거
- 장면 전환, 시간 역전, 긴 공백, 해상도 변경 시 추적 상태 초기화
- Lab 상의 색상과 트랙별 투표를 이용한 A/B 팀 분류
- 화면 좌표 궤적과 `scene_id + track_id` 저장
- 단일 정지 장면 수동 호모그래피와 보정 범위 밖 좌표 차단
- 녹색 영역의 사각형을 이용한 초기 자동 보정 실험
- 경기장 좌표 기반 팀 폭, 최소 간격, 기준 포메이션 편차
- 영상·시간바·전술 보드·이벤트를 포함한 로컬 GUI

기준 영상 `manvsmci.mp4`의 과거 기록은 약 980프레임, 9.30fps다. 정확도 기준선은 아직 수동 정답이 부족하므로 단계 0에서 새로 만든다.

현재 샌드박스에서는 pytest 임시 폴더 접근 거부가 발생하여 전체 테스트의 유효한 통과/실패 수를 확정하지 못했다. 구현 시작 전 일반 로컬 실행 환경에서 기준 테스트를 다시 통과시키고 결과를 기록한다.

## 5. 목표 구조

```text
입력 프레임
  ├─ 장면/입력 상태 검사
  ├─ 축구 객체 탐지 ─ 추적 ─ 역할·팀 안정화
  └─ 경기장 키포인트 ─ 보정 후보 ─ 품질 검증 ─ 시간 안정화
                                      │
                 선수 발점·공 중심점 ─┘
                          │
                  경기장 미터 좌표
                          │
            전술 보드·지표·이벤트·진단 로그
```

각 단계는 다음처럼 교체 가능한 경계를 갖게 한다.

- `Detector`: 사람 전용 기본 모델과 축구 전용 모델
- `Tracker`: ByteTrack 기본값과 BoT-SORT 실험값
- `PitchCalibrator`: 수동, 키포인트 자동, 향후 PnLCalib 실험
- `TeamAssigner`: 현재 Lab 기준선과 향후 임베딩 기반 실험
- `BallAnalyzer`: 공 추적, 소유 후보, 패스 후보

## 6. 단계별 작업

### 단계 0 — 기준선과 라이선스 고정

작업:

- 전체 자동 테스트를 정상 로컬 임시 폴더에서 실행해 결과를 기록한다.
- 현재 출력 스키마와 대표 프레임을 회귀 검사용 fixture로 고정한다.
- 전술캠 2개 이상과 방송 카메라 1개 이상의 짧은 평가 클립을 선정한다.
- 최소 100프레임에 사람 박스, 팀, 추적 ID, 경기장 기준점을 수동 표기한다.
- 참고 저장소의 기준 커밋과 코드·모델·데이터 라이선스를 표로 남긴다.

통과 조건:

- 기존 테스트가 모두 통과하고 대표 영상 결과를 재생할 수 있다.
- 평가 클립과 정답 파일의 출처·용도·재배포 가능 여부가 문서화된다.
- 이후 단계에서 비교할 FPS, 탐지율, ID 전환 수, 팀 정확도, 보정 오차가 산출된다.

### 단계 1 — 모듈 경계와 진단 데이터

작업:

- 탐지기, 트래커, 보정기의 공통 인터페이스와 설정 객체를 도입한다.
- `frames.jsonl`에 역할, 객체 신뢰도, 보정 상태, 보정 오차, 보정 age를 선택 필드로 추가한다.
- 기존 결과 파일을 계속 읽을 수 있도록 스키마 버전과 하위 호환 처리를 추가한다.
- 기능별 플래그를 추가하되 GUI 기본값은 기존 동작으로 둔다.

통과 조건:

- 새 기능을 모두 껐을 때 기존 출력과 의미가 같다.
- 각 모듈을 테스트 대역으로 교체할 수 있고 GUI 없이 단위 테스트할 수 있다.
- 중간 실패가 발생해도 이미 처리한 결과와 실패 이유가 저장된다.

### 단계 2 — 자동 경기장 보정

작업:

- Roboflow/Simo 방식의 경기장 키포인트 모델을 별도 선택 기능으로 연결한다.
- 4점 고정 변환 대신 다수 대응점과 RANSAC으로 보정 후보를 계산한다.
- 최소 점 개수, 분포, inlier 비율, 재투영 오차, 경기장 크기·방향, 프레임 간 이동량을 검사한다.
- 유효한 절대 보정 사이에서는 제한된 광학 흐름을 사용하되 누적 오차 한도와 최대 재사용 프레임을 둔다.
- 자동 보정이 불확실하면 좌표를 숨기거나 수동 보정으로 돌아가며, 마지막 값을 무기한 사용하지 않는다.

통과 조건:

- 별도 검증점의 중앙 위치 오차와 10m 이상 구간 거리 오차가 수동 기준에 근접한다.
- 정지 전술캠에서 유효 보정 프레임 비율 90% 이상을 목표로 측정한다.
- 컷 전환이나 키포인트 오검출 시 전술 보드가 반대편 또는 경기장 밖으로 순간 이동하지 않는다.
- 통과하지 못하면 자동 보정은 실험 기능으로만 남긴다.

### 단계 3 — 추적기 비교와 카메라 이동 대응

작업:

- 같은 탐지 결과로 ByteTrack과 BoT-SORT를 재생할 수 있는 비교 도구를 만든다.
- BoT-SORT의 전역 카메라 이동 보정과 트랙 버퍼를 먼저 시험한다.
- 장면 경계를 넘는 ID 유지나 실제 선수 신원 확인은 시도하지 않는다.
- ID 전환, 단편화, 트랙 수명, 처리 속도를 클립별로 기록한다.

통과 조건:

- 동일 클립에서 ID 전환이 기준선보다 줄고 거짓 장기 트랙이 늘지 않는다.
- 처리 속도 저하가 사용 가능한 범위인지 수치로 제시한다.
- 개선이 특정 클립에만 나타나면 전역 기본값으로 바꾸지 않고 입력 유형별 옵션으로 둔다.

### 단계 4 — 축구 전용 탐지와 팀 안정화

작업:

- 선수, 골키퍼, 심판, 공 클래스가 있는 축구 전용 가중치를 별도 프로필로 연결한다.
- 현재 Lab 팀 분류를 기준선으로 두고, 트랙별 다중 프레임 투표와 미확인 거부 규칙을 강화한다.
- 골키퍼와 심판을 억지로 A/B 팀에 넣지 않는다.
- 임베딩 기반 팀 분류는 CPU 비용과 실제 정확도가 Lab 방식보다 유리할 때만 채택한다.

통과 조건:

- 수동 표본에서 선수/심판/골키퍼 혼동 행렬과 팀 분류 정확도를 보고한다.
- 목표 팀 정확도는 판정 가능한 표본 기준 95% 이상이며, 애매한 표본을 미확인으로 남긴 비율도 함께 공개한다.
- 일반 사람 탐지 모델을 사용하는 기존 경로가 계속 동작한다.

### 단계 5 — 공, 점유율, 패스 후보

작업:

- 작은 공을 위한 전용 입력 크기 또는 타일 추론을 실험한다.
- 짧은 누락을 보간하되 공이 장시간 보이지 않으면 위치를 추측하지 않는다.
- 공과 가장 가까운 선수, 거리 임계값, 연속 프레임 조건으로 소유 후보를 정한다.
- 같은 팀의 소유 트랙이 바뀌고 중간 공 이동이 확인될 때만 패스 후보로 기록한다.
- 결과 표현은 `확정 패스`가 아니라 `패스 후보`로 한다.

통과 조건:

- 공이 보이는 수동 표본에서 탐지 coverage, precision, 위치 오차를 측정한다.
- 점유율과 패스 후보는 수동 태그 클립에서 precision/recall을 제시한다.
- 기준 미달이면 공 궤적만 제공하고 파생 해석은 비활성화한다.

### 단계 6 — 전술 화면과 리포트 연결

작업:

- 영상과 전술 보드에 보정 유효/불확실/만료 상태를 표시한다.
- 선수 궤적, 팀 폭, 라인 간격, 히트맵, 점유 후보를 같은 시간축으로 탐색하게 한다.
- 물리적으로 불가능한 속도나 보정 점프는 지표 누적에서 제외하고 이유를 기록한다.
- 이벤트 전후 비교에는 충분한 선수 좌표와 유효 보정이 있는 구간만 사용한다.

통과 조건:

- 시간바 이동 후 영상, 전술 보드, 지표, 이벤트가 같은 프레임을 가리킨다.
- 좌표나 팀 정보가 부족할 때 오해를 부르는 0값 대신 `계산 불가`를 표시한다.
- 한 영상 분석을 중지하거나 실패해도 기존 부분 결과를 다시 열 수 있다.

### 단계 7 — 최종 검증과 병합 판단

작업:

- 기준 브랜치와 새 브랜치를 동일 영상·동일 설정으로 비교한다.
- 정확도, 속도, 메모리, 출력 크기, 설치 용량을 표로 작성한다.
- Windows 새 설치, CPU 전용 실행, 태블릿 입력, 파일 입력을 각각 점검한다.
- 사용자 문서, 제3자 고지, 모델 다운로드 방법, 알려진 한계를 갱신한다.

병합 조건:

- 기존 회귀 테스트와 새 기능 테스트가 모두 통과한다.
- 기본 경로에서 치명적 성능 회귀나 결과 손상이 없다.
- 자동 보정과 파생 지표가 신뢰도 부족 시 스스로 비활성화된다.
- 포함한 모든 코드와 모델의 배포 조건을 충족한다.

## 7. 구현 순서와 커밋 단위

한 커밋에 여러 위험 요소를 섞지 않는다.

1. `docs: record OSS sources, commits, and licenses`
2. `test: add baseline clips and evaluation schema`
3. `refactor: isolate detector tracker and calibrator interfaces`
4. `feat: persist calibration diagnostics`
5. `feat: add pitch-keypoint calibration experiment`
6. `feat: validate and smooth moving-camera calibration`
7. `experiment: compare ByteTrack and BoT-SORT`
8. `feat: add football-role detection profile`
9. `feat: add ball tracking and possession candidates`
10. `feat: expose diagnostics and tactical overlays in UI`
11. `docs: publish benchmark and remaining limitations`

각 기능 커밋에는 단위 테스트를 포함하고, 모델 파일과 원본 경기 영상은 Git에 직접 넣지 않는다.

## 10. 완료 정의

이 브랜치는 단순히 기능이 화면에 나타나는 것으로 완료하지 않는다. 대표 전술캠에서 자동 보정과 추적 개선이 수치로 확인되고, 불확실한 구간은 숨기며, 기존 수동 흐름이 보존되고, 라이선스 고지가 끝난 상태를 완료로 본다.

단계 0~4를 최소 병합 범위로 삼고, 공·점유율·패스 후보인 단계 5 이후는 앞 단계 정확도가 확보된 경우에만 진행한다.
