# 제품 계획

개정: 2026-10-01. 2026-09-15 프로젝트 플랜과 전술 분석 설계를 요약해 합쳤다. 개발 순서와 브랜치는 [개발_계획.md](개발_계획.md), 현재 진행은 [개발현황.md](개발현황.md)를 본다.

## 1. 목표

노트북에서 보는 축구 영상을 분석해 선수의 팀·위치·간격과 시간에 따른 배치 변화를 보여주는 Windows 프로그램이다. 외부 AI API 없이 로컬에서 동작한다.

- **주 대상은 아마추어 팀이 고정 전술캠으로 찍은 자체 경기**다. 관중석 높은 곳에 삼각대로 고정하면 22명이 계속 보이고 호모그래피를 한 번만 보정해도 된다. 프로 중계는 줌·패닝·컷이 잦아 22명이 동시에 잡히는 시간이 거의 없어 전술 분석에 맞지 않는다.
- 입력은 로컬 파일, 태블릿 IP Webcam(MJPEG), 화면 영역 캡처다. 쿠팡플레이 같은 DRM 영상은 캡처가 검게 나오며 우회하지 않는다. Google Colab은 녹화 영상의 전체 분석에만 쓴다.
- 핵심 결과: 선수 탐지와 팀 A/B 표시, 장면 내 임시 추적 번호, 유효한 보정 구간의 미터 단위 간격, 관측 선수 기준 폭·깊이·배치 변화.

## 2. 정직성 원칙

- 선수 번호는 임시 추적 ID이며 실제 등번호나 신원이 아니다.
- 화면 밖 선수는 미관측이다. 거리·배치는 관측되고 좌표 변환이 유효한 선수에만 계산한다.
- 보정이 없거나 만료되면 좌표를 숨기고 `계산 불가`로 표시한다. 미측정 값을 0으로 기록하지 않는다.
- 측정하지 않은 정확도·실시간 성능을 주장하지 않는다. 문서의 수치 목표는 달성 결과가 아니라 초기 목표다.
- 공 소유권 근거 없이 공격·수비를 자동 확정하지 않는다. 패스는 `후보`로만 표기한다.
- 제외 범위: 얼굴 인식·장기 ReID, 등번호 OCR, 오프사이드·득점·파울 자동 판정, 3D 자세, 근거 없는 AI 코칭 문장, DRM 우회.

## 3. 전술 분석 설계

### 기준 포메이션과 편차
1. 팀이 포메이션 프리셋(4-4-2 등)을 고르고 경기장 위에서 드래그로 조정해 **수비 시·공격 시 기준 배치** 두 개를 저장한다(구현됨, `formation.json`).
2. 추적된 선수 위치를 기준과 비교한다. 좌표 오차 대신 코치가 쓰는 말로 바꾼다: 라인 간 거리, 팀 폭, 인접 선수 간격, 팀 평균 이탈도.
3. "얼마나 벗어나면 이탈인가"는 절대값(예: 센터백 8m)으로 정하지 않는다. 그 팀의 경기 평균과 표준편차를 기준선으로 삼아 z-score 1.5~2 이상을 `평소보다 벌어짐`으로 본다. 탐지·좌표 오차보다 확실히 큰 편차만 인정한다.
4. 1단계는 누가 누구인지 몰라도 계산되는 팀 집계 지표만 쓴다. 선수별 슬롯 매칭은 추적이 안정된 뒤에 한다.

### 이벤트와 브리핑
- 자동 이벤트 인식은 공 추적이 필요해 후순위다. 먼저 코치가 영상에서 시점(실점, 위험 장면, 빌드업 시작·결과)을 수동으로 찍는 이벤트 태깅을 쓴다(구현됨, `events.json`). 태그 전후 5~10초의 지표를 계산한다.
- 브리핑은 `장면 + 지표 + 기준 비교`로 구성한다: 국면별 평균 이탈도, 편차가 큰 순간 상위 N개와 기준 배치 위에 겹친 배치도, 한 줄 설명, 경기 요약 패턴.
- 표본이 적은 처음 한두 경기는 "기준 데이터가 적어 참고용"이라고 명시한다.

### 빌드업 분석 (후속)
- 측정 후보: 후방 수적 우위·열세, 패싱 레인 차단 여부, 빌드업 국면의 라인 간 거리, 폭 사용. 뒷공간 침투 같은 시간 움직임 지표는 추적이 안정된 뒤에 한다.
- 수동 태깅한 성공·실패 시도의 지표 평균을 비교해 "왜 안 풀리는지"의 원인 분포를 낸다.

### 팀별 데이터 저장 (후속)
- 기준선은 `팀 + 전술 프로파일` 단위로 누적한다. 포메이션이 다르면 정상 범위가 다르므로 한 기준선에 섞지 않는다. 새 경기 지표는 평균·표준편차에 온라인 갱신으로 반영한다.

## 4. 구조

```text
입력 → 장면/입력 상태 확인 → 선수 탐지 → 추적 → 팀 분류
     → 발 위치 → 경기장 좌표 변환(보정) → 신뢰도 검사 → 간격·배치 지표 → 영상·전술 보드·이벤트
```

- **보정:** 영상 지면 → 105m × 68m 경기장 호모그래피. 수동은 알려진 기준점 4개 이상, 한 번 보정해 고정 카메라 구간에 재사용한다. 외삽 영역·노후 보정·큰 오차 좌표는 출력하지 않는다. 검증용 기준점은 보정 계산에 쓰지 않고 독립 평가에 남긴다.
- **실시간:** 캡처·분석·표시를 분리하고 대기열을 1개로 제한하며 오래된 프레임을 버린다. 입력 중단·검은 화면·크기 변경은 상태를 초기화하고 낡은 숫자를 남기지 않는다.
- **프레임 기록:** 입력·장면·프레임 ID와 시각, 박스, 임시 추적 ID, 팀과 분류 상태, 필드 좌표 또는 미측정, 보정 상태·진단.

## 5. 단계별 목표 (초기 수용 목표, 달성 결과 아님)

| 단계 | 내용 | 초기 통과 목표 | 상태 |
|---|---|---|---|
| 0 | 환경·입력 검증 | 반복 재생 가능한 샘플, 캡처 성공·실패 기록 | 구현됨 |
| 1 | 탐지·거리 변환 기준 성능 | 30프레임 수동 정답, 정밀도·재현율 90%(IoU 0.5), 10m 이상 기준 선분 상대 오차 중앙값 10% 이하 | **미검증** |
| 2 | 영상 기반 최소 제품 | 팀 정확도 95%와 미분류율 공개, 명확한 선수 5명 10초 ID 전환 1회 이하 | 구현됨, 정량 미검증 |
| 3 | 실시간 최소 제품 | 10fps 이상, 지연 95백분위 500ms 이하, 10분 연속 | 미리보기만, 장시간 미검증 |
| 4 | 움직이는 카메라 대응 | 주 카메라 구간 유효 출력 80% | 자동 보정 개발 중 |
| 5 | 배치 변화·전술 보조 | 모든 문장이 지표로 설명됨 | 일부(간격·편차) |
| 6 | 사용성·배포 | 새 환경 설치·실행 검증 | 일부 |

검증 원칙: 개발용과 최종 검증용 영상을 분리하고, 평균만이 아니라 오차 분포·미출력 비율·지연을 함께 기록한다. 보정 수학, 무효 데이터 전파, 장면 초기화, 대기열 제한은 자동 테스트로 확인한다.

## 6. 기술 선택

Python 3.13, OpenCV·NumPy, mss(화면 캡처), Ultralytics YOLO11n + ByteTrack, 상의 Lab 색상 + 시간 투표 팀 분류, Tkinter UI. 설치 이후 기본 분석은 외부 API 키가 필요 없다. 모델 세대는 문서로 고정하지 않고 설치 시 실제 성능으로 확인한다. 라이선스는 [../LICENSE](../LICENSE)와 [../THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)를 따른다.
