# 개발 계획

개정: 2026-10-01. 기존 `오픈소스_적용_계획.md`를 대체한다. 제품 방향은 [제품_계획.md](제품_계획.md), 진행 기록은 [개발현황.md](개발현황.md)를 본다.

## 1. 작업 규칙

- 한 번에 커밋 단위 하나만 구현한다. 구현 중에는 커밋·브랜치 생성·push를 하지 않고 자동 테스트만 돌린다.
- 단위가 끝나면 개발현황.md에 로그(수정 내용과 이유, 영향 범위, 테스트 결과, 직접 확인 절차, 정상·실패 증상)를 남기고 추천 커밋 메시지와 함께 보고한 뒤 사용자의 커밋 신호를 기다린다.
- 브랜치는 `main`(안정), `develop`(업데이트용, 기본 브랜치), `hotfix`(급한 수정) 셋만 상시 유지한다. 기능 브랜치는 `develop`에서 따서 `develop`으로 PR을 올리고 병합 후 삭제한다. 병합 방식은 squash다. `hotfix`는 `main`으로 PR을 올린 뒤 `develop`에도 반영한다.
- 새 기능은 설정으로 끌 수 있어야 하고, 불확실하면 스스로 비활성화한다. 수동 보정은 기준이자 대체 경로로 유지한다.

라이선스 부담을 줄이기 위해 **외부 코드와 가중치를 가져오지 않는 것을 기본**으로 한다.

프로젝트 자체는 MIT다. 가중치를 못 구해도 수동 보정이 있어 개발은 막히지 않는다.

## 3. 현재 위치

경기장 자동 보정(단계 2) 기반 3/5 완료: 분석 계약·진단 스키마, RANSAC 키포인트 보정 후보와 품질 검증, 시간 안정화와 stale 차단, 기준 배치·보정 실행 수정과 도움말. 아직 키포인트 모델과 GUI에는 연결되지 않았다.

## 5. 단계별 통과 조건 요약

- **자동 보정(B1~B2):** 별도 검증점의 중앙 위치 오차와 10m 이상 구간 거리 오차가 수동 기준에 근접하고, 정지 전술캠에서 유효 보정 프레임 비율 90%를 목표로 측정한다. 컷 전환·오검출에서 전술 보드가 순간 이동하지 않는다. 미달이면 실험 기능으로만 둔다.
- **추적(B3):** 같은 클립에서 ID 전환이 기준선보다 줄고 거짓 장기 트랙이 늘지 않는다. 특정 클립에서만 개선되면 입력 유형별 옵션으로 둔다.
- **탐지·팀(B4):** 역할 혼동 행렬과 팀 정확도(판정 가능 표본 기준 95%)를 미확인 비율과 함께 공개한다. 기존 경로가 계속 동작한다.
- **공(B5):** 수동 표본에서 coverage·precision·위치 오차를 측정하고, 기준 미달이면 궤적만 제공한다.
- **병합 조건:** 기존 회귀 테스트와 새 테스트 통과, 기본 경로에 치명적 성능 회귀 없음, 자동 보정·파생 지표가 신뢰도 부족 시 스스로 비활성화됨.

## 6. 사용자 입력이 필요한 지점

- 평가 클립(전술캠 2개 이상, 방송 1개 이상)과 100프레임 이상의 수동 기준점 표기 — B2 시작 전. 영상과 정답 파일은 Git에 넣지 않는다.
- 외부 가중치 사용 여부 — 1-3 직전.
- Ultralytics AGPL 대응 — 외부 배포 전.
