# 오프더볼 (Off the Ball) — 프로젝트 기획서

## 1. 프로젝트 개요

**한 줄 정의**: 노트북에서 재생 중인 축구 중계 영상(쿠팡플레이 등)을 실시간으로 화면 캡처하여, 선수들의 위치·포메이션·간격을 인식하고 전술 흐름을 분석해주는 시스템.

**핵심 기능**
- 한 팀의 공격/수비 상황에서 나타나는 전체 포메이션 및 전술 흐름 시각화
- 같은 팀 선수 간의 간격(거리)을 화면에 실시간 표시
- 실시간 스트리밍 방식으로 동작 (녹화 영상이 아닌 지금 보고 있는 화면 기준)

**개발자 배경**: 코딩 경험은 있으나 이 정도 규모의 프로젝트는 처음 (바이브코딩 중심). → 처음부터 다 짜기보다 검증된 오픈소스를 조합하는 방식으로 진행.

---

## 2. 시스템 구조 (2층 구조)

이 프로젝트는 반드시 두 개의 층으로 나눠서 생각해야 합니다.

### 1층 — 데이터 파이프라인 (전통적인 컴퓨터 비전, LLM 불필요)
```
화면 캡처 → 선수 탐지 → 선수 추적(ID 유지) → 팀 색상 구분
→ 좌표 변환(픽셀→실제 필드 좌표) → 간격/포메이션 계산 → 화면 오버레이
```
이 층은 실시간으로 계속 돌아가는 코드 파이프라인입니다. 정밀한 숫자(거리, 좌표)를 다루는 부분이라 LLM이 아니라 전통적인 CV 알고리즘이 담당합니다.

### 2층 — AI 전술 해설 (Claude 담당)
1층에서 몇 초마다 뽑아낸 "좌표/간격 데이터"를 텍스트로 정리해 Claude API에 전달하고, 자연어로 된 전술 해설("지금 수비라인이 좁아지고 있다" 등)을 받아옵니다. Claude는 원본 영상을 직접 보는 게 아니라, 1층이 계산한 숫자 데이터를 보고 해석하는 역할입니다.

> 왜 이렇게 나누나: LLM은 화면을 보고 눈대중 설명은 할 수 있어도, 프레임마다 일관된 선수 ID를 유지하고 미터 단위 거리를 정확히 계산하는 건 못합니다. 그건 전용 CV 모델의 영역입니다.

---

## 3. 기술 스택 요약

| 영역 | 기술 후보 | 비고 |
|---|---|---|
| 화면 캡처 | Python `mss` 라이브러리 | 노트북 화면을 초당 여러 번 스크린샷, 웹캠/태블릿보다 훨씬 안정적 |
| 선수 탐지 | YOLOv8 (사전학습 모델) | 직접 학습 불필요, 사람 탐지용으로 바로 사용 가능 |
| 선수 추적 | ByteTrack / DeepSORT | 프레임 간 같은 선수에게 같은 ID 부여 |
| 팀 구분 | 색상 클러스터링 (K-means 등) | 박스 내부 유니폼 색상 분석 |
| 좌표 변환 | Homography (OpenCV `findHomography`) | 픽셀 좌표 → 실제 필드 좌표(미터), 기술적으로 가장 어려운 부분 |
| 오버레이 렌더링 | OpenCV | 점선, 숫자, 박스 등 그리기 |
| 전술 해설 | Claude API | 좌표 데이터를 텍스트로 요약해 전달 |

## 4. 단계별 개발 플랜

### Phase 0 — 준비
- 목표: 개발 환경 세팅
- 할 일: Python 설치, YOLOv8·OpenCV·mss 라이브러리 설치, 쿠팡플레이 영상 짧게 녹화(테스트용 샘플 확보)
- 완료 기준: 샘플 영상 파일 확보 + 라이브러리 정상 설치 확인

### Phase 1 — MVP: 녹화 영상 + 선수 탐지
- 목표: "영상에서 사람 위치에 박스가 그려진다"는 최소 결과물 확인
- 할 일: 녹화한 샘플 영상을 프레임 단위로 읽어서 YOLOv8로 사람 탐지 → 박스만 그려서 저장
- 완료 기준: 출력 영상에서 선수마다 박스가 표시됨 (번호/추적/팀구분 없음, 탐지만)
- 난이도: ★☆☆☆☆ (오픈소스 그대로 갖다 쓰면 됨)

### Phase 2 — 선수 추적으로 ID 유지
- 목표: 프레임이 바뀌어도 같은 선수는 같은 번호 유지
- 할 일: ByteTrack(또는 유사 추적기)을 탐지 결과에 연결
- 완료 기준: "3번 선수가 이동했다"를 프레임 간 추적 가능
- 난이도: ★★☆☆☆

### Phase 3 — 팀 색상 구분
- 목표: 두 팀 + 심판을 자동으로 구분
- 할 일: 각 박스 내부 색상 샘플링 → 클러스터링으로 팀 분류
- 완료 기준: 박스 색상이 팀별로 다르게 표시됨
- 난이도: ★★☆☆☆

### Phase 4 — 좌표 변환 (호모그래피) ⚠️ 최대 난관
- 목표: 화면 픽셀 거리가 아닌 실제 필드 미터 단위 거리 확보
- 할 일: 경기장 라인(페널티박스, 하프라인 등)을 기준점으로 호모그래피 변환 행렬 계산. 카메라가 계속 움직이므로 프레임마다(또는 일정 주기로) 재보정 필요
- 완료 기준: 알고 있는 실제 거리(예: 페널티박스 폭 40.3m)와 계산값이 비슷하게 나옴
- 난이도: ★★★★★
- 참고: 이 단계가 너무 어려우면 Phase 5의 "간격 표시"를 픽셀 기준 상대값(정확한 미터 대신 "가깝다/멀다" 정도)으로 낮춰서 진행하는 것도 방법

### Phase 5 — 간격 계산 및 오버레이
- 목표: 같은 팀 인접 선수 간 거리, 수비 라인 폭 등을 계산해 화면에 표시
- 할 일: 변환된 좌표로 거리 계산 → 점선 + 숫자로 오버레이 렌더링
- 완료 기준: 처음 보여드린 목업처럼 선수 간 점선+거리 수치가 화면에 표시됨
- 난이도: ★★☆☆☆ (Phase 4가 끝나면 비교적 쉬움)

### Phase 6 — 실시간 화면 캡처로 전환
- 목표: 녹화 영상이 아닌 지금 재생 중인 화면을 실시간으로 처리
- 할 일: `mss`로 노트북 화면 특정 영역을 초당 여러 번 캡처해 동일 파이프라인에 흘려보냄
- 완료 기준: 쿠팡플레이를 틀어놓고 실시간으로 오버레이가 따라옴
- 난이도: ★★★☆☆ (처리 속도 최적화 필요)

### Phase 7 — Claude 연동 전술 해설
- 목표: 숫자 데이터를 자연어 해설로 변환
- 할 일: 몇 초 주기로 좌표/간격 데이터를 텍스트로 정리해 Claude API 호출, 응답을 화면에 표시
- 완료 기준: "지금 오른쪽 측면 공간이 열려있다" 같은 문장이 실시간으로 뜸
- 난이도: ★★☆☆☆

## 5. 리스크 및 주의사항

- **카메라 앵글 변화**: 중계 카메라가 팬/줌을 계속하므로 Phase 4의 좌표 변환을 한 번만 계산하면 안 되고 주기적으로 재보정해야 함
- **처리 속도**: 탐지+추적+변환을 매 프레임마다 하면 노트북 사양에 따라 느려질 수 있음 → 프레임을 건너뛰며 처리(예: 5프레임당 1번)하는 것도 방법
- **저작권/이용 범위**: 개인적인 분석·학습 목적으로만 사용하고, 캡처한 영상을 외부에 배포하지 않는 것을 권장
- **완벽한 정확도는 처음부터 기대하지 않기**: Phase 4(호모그래피)는 실제 스포츠 분석 업체들도 어려워하는 부분. 처음엔 오차가 있어도 정상
